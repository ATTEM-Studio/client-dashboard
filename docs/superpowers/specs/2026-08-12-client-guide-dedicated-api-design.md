# 정보안내문 전용 저장 흐름 설계

## 목표

기존에 전달된 `?guide=...` 링크를 유지하면서 정보안내문 저장·조회·제출을 전용 API 흐름으로 분리한다. 관리자 업체 탭과 고객용 링크가 같은 안내문 문서를 안정적으로 공유하고, 재접속·새로고침·제출 후 수정에서도 데이터가 사라지지 않게 한다.

## 범위

- 기존 영구 링크 형식 유지
- 고객용 안내문 조회, 임시저장, 최종 제출 API 분리
- 관리자용 조회 및 내부 검토 저장 분리
- 저장 실패 상태와 재시도 표시 개선
- 기존 안내문 데이터의 호환 및 자동 복구
- 기존 계약서·체크리스트·리포트 흐름 변경 없음

## 데이터와 API

전용 엔드포인트는 `api/guide.js`로 둔다.

- `GET /api/guide?id=guide_...`
  - 공개: 답변, 제출 상태, 생성·수정 시각, 서비스 문맥만 반환
  - 내부 메모·검토 상태는 반환하지 않음
- `POST /api/guide?id=guide_...&action=save`
  - 공개 입력 필드만 허용
  - 서버의 최신 답변과 병합하고 수정 시각을 서버에서 기록
- `POST /api/guide?id=guide_...&action=submit`
  - 답변 병합 후 제출 시각을 한 번만 기록
  - 제출 후 수정은 같은 링크로 허용하되 제출 시각과 최신 수정 시각을 분리
- 관리자 인증 요청은 같은 전용 API를 사용해 최신 공개 문서를 조회한다.
- 내부 검토는 `guide-review:<id>`에 별도로 저장하며 관리자 인증 없이는 읽거나 쓸 수 없다.

기존 `guide:<id>`와 `guide-issue:<clientId>` 데이터가 있으면 전용 API가 읽을 때 호환하고, 성공적인 저장 시 전용 저장 형식으로 정규화한다. 기존 링크를 재발급하지 않는다.

## 동시성·오류 처리

- 공개 저장은 Redis 원자 연산으로 최신 서버 문서에 병합한다.
- 오래된 브라우저 요청이 제출 상태나 최신 답변을 되돌리지 못하게 한다.
- 공개 요청은 인증 없이 허용하되, 형식이 맞는 `guide_` ID만 처리한다.
- 잘못된 ID는 안내문 없음, 저장 실패는 연결 오류, 서버 응답 오류는 서버 오류로 구분한다.
- 고객 화면은 마지막 성공 답변을 `sessionStorage`에 보관하고 재접속 시 즉시 복원한 뒤 서버 최신본으로 갱신한다.
- 자동 저장은 500ms 지연과 요청 직렬화를 유지하되 전용 API를 사용한다.

## 화면 흐름

### 고객용 링크

1. 링크 진입 시 서버 문서를 조회한다.
2. 저장된 답변을 즉시 화면에 표시한다.
3. 입력 변경 후 자동 저장 상태를 `저장 중`, `저장됨`, `저장 실패`로 표시한다.
4. 실패 시 같은 입력을 유지한 채 재시도한다.
5. 제출 성공 시 완료 화면을 표시한다.
6. 같은 링크 재접속 시 제출 답변을 다시 보여주고 수정할 수 있다.

### 관리자 업체 탭

1. 업체의 기존 `guideId`를 우선 사용한다.
2. 누락된 경우 서버 발급 예약 정보에서 복구한다.
3. 공개 문서 조회와 내부 검토 조회를 별도로 수행한다.
4. 공개 문서 조회 실패 시 링크를 지우지 않고 재시도 버튼을 표시한다.
5. 링크 복사·미리보기는 기존 주소를 그대로 사용한다.

## 보안 및 호환성

- 공개 응답에는 내부 메모·검토 상태·인증 토큰을 포함하지 않는다.
- 공개 저장 필드는 기존 13개 답변 필드로 제한한다.
- 서비스 문맥과 안내문 ID는 서버 저장값을 우선한다.
- 기존 범용 데이터 API의 다른 기능은 영향을 받지 않는다.

## 테스트 기준

다음 시나리오를 자동화한다.

- 기존 링크 GET이 공개 답변을 반환한다.
- 저장 후 새로고침·재접속에서 최신 답변이 유지된다.
- 제출 후 같은 링크에서 제출 상태와 답변이 유지된다.
- 제출 중 오래된 임시저장이 제출 상태를 되돌리지 않는다.
- 공개 응답에 내부 검토 정보가 포함되지 않는다.
- 관리자 탭이 누락된 `guideId`를 예약 정보로 복구한다.
- 전용 API 오류가 화면의 재시도 상태로 연결된다.
- 기존 `guide:` 데이터가 전용 API에서 정상 호환된다.

## 완료 조건

- 기존에 발급된 링크를 변경하지 않고 고객이 재접속할 수 있다.
- 관리자 업체 탭에서 링크·답변·제출 상태가 반복 진입에도 유지된다.
- 자동 저장과 최종 제출이 서로의 데이터를 덮어쓰지 않는다.
- 내부 검토 정보가 고객 링크에 노출되지 않는다.
- 관련 테스트와 전체 회귀 테스트가 통과한다.
