# 적극형 반응성 모션 시스템 설계

## 목적

대시보드의 버튼, 카드, 메뉴, 탭, 팝업, 저장 상태, 그래프와 달력에 일관된 반응성을 적용한다. 사용자는 누른 대상과 이동 방향, 처리 결과를 즉시 이해할 수 있어야 한다. 모션은 장식이 아니라 조작 결과와 화면의 공간 관계를 설명하는 수단으로 사용한다.

## 적용 원칙

- 입력 즉시 반응한다. 클릭이나 터치가 끝날 때까지 기다리지 않고 눌림 상태를 보여준다.
- 화면 요소는 나타난 위치와 사라지는 위치가 연결되어야 한다.
- 이동 중 다시 조작해도 현재 상태에서 자연스럽게 이어져야 한다.
- 변형은 주로 `transform`과 `opacity`를 사용해 모바일 성능을 유지한다.
- 업무 판단을 방해하는 반복, 장시간, 번쩍임 효과는 사용하지 않는다.
- 운영체제의 모션 최소화 설정을 존중한다.

## 공통 모션 토큰

모든 화면은 공통 속도와 곡선을 사용한다.

- 즉시 반응: 90~120ms. 버튼 눌림, 체크 선택, 행 하이라이트에 사용한다.
- 짧은 전환: 160~220ms. 탭, 배지, 토스트, 작은 메뉴에 사용한다.
- 공간 전환: 380~520ms. 카드 확장, 상세 진입, 팝업에 사용한다.
- 적극형 스프링: 빠르게 목표에 접근한 뒤 아주 작게 안착하는 곡선을 사용한다.
- 일반 감속: 그래프, 게이지, 목록 정렬처럼 튀는 느낌이 불필요한 곳에 사용한다.

CSS 사용자 속성으로 값을 한곳에서 관리해 화면별 임의 속도 사용을 막는다. 기존 전환 효과는 이 토큰으로 통합한다.

## 1단계: 공통 조작 요소

### 버튼과 클릭 가능한 카드

- 누르는 순간 크기가 약 2~3% 줄고 표면 색 또는 그림자가 바뀐다.
- 손을 떼면 짧은 스프링으로 원래 크기에 복귀한다.
- 비활성 버튼은 눌림 효과를 내지 않는다.
- 업체 카드 전체를 클릭 가능한 대상으로 유지하고, 키보드 포커스에도 동일한 시각 피드백을 제공한다.

### 상단 토글 메뉴

- 메뉴는 트리거 아이콘을 기준점으로 열리고 닫힌다.
- 배경은 짧게 흐려지고 메뉴 항목은 20~30ms 간격으로 순차 안착한다.
- 바깥 영역 클릭, Escape, 메뉴 선택으로 닫을 수 있다.
- 닫는 도중 다시 열면 현재 위치에서 방향을 바꿔 이어진다.

### 탭

- 활성 표시선 또는 배경이 선택한 탭으로 이동한다.
- 내용은 이동 방향을 암시하는 아주 짧은 이동과 페이드로 교체한다.
- 연속 클릭 시 오래된 전환을 기다리지 않고 마지막 선택 상태로 수렴한다.

### 팝업과 알림

- 팝업은 선택한 대상과 가까운 방향에서 확대·안착한다.
- 배경 흐림은 콘텐츠보다 먼저 시작하고 닫을 때 반대로 진행한다.
- 저장 성공은 짧은 상승과 체크 표시, 실패는 흔들림 없이 색과 명확한 문구로 알린다.
- 토스트는 자동으로 사라지되 중요한 실패 메시지에는 재시도 동작을 제공한다.

## 2단계: 업체 상세와 업무 흐름

### 업체 상세 진입

- 홈의 업체 카드는 눌림 반응 후 상세 화면으로 연결된다.
- 선택 카드와 상세 헤더가 같은 개체처럼 느껴지도록 크기와 위치 변화를 연결한다.
- 뒤로가기는 진입 방향을 반대로 재생해 홈에서의 위치 관계를 보존한다.

### 체크리스트

- 완료 체크 즉시 색, 체크 표시, 완료 수치가 함께 반응한다.
- 저장 요청과 서버 확정 상태를 구분한다. 처리 중에는 짧은 진행 표시, 성공 시 안정된 초록 상태, 실패 시 원래 상태 복원과 재시도를 제공한다.
- 주차 토글은 내용 높이를 부드럽게 열고 닫되 긴 목록에서도 프레임 저하가 없도록 구현한다.
- 오늘 업무의 파랑·초록·노랑 상태 의미는 기존 규칙을 유지한다.

### 달력

- 날짜 선택 시 날짜 칸이 즉시 강조되고 일별 팝업이 해당 칸에서 이어져 나온다.
- 체크 완료 후 날짜의 미완료 테두리와 배지가 자연스럽게 갱신된다.
- 월 이동은 좌우 방향을 명확히 보여주되 빠르게 연속 이동할 수 있어야 한다.

## 3단계: 데이터 시각화

- 그래프는 화면 최초 진입과 조회 조건 변경 시 왼쪽에서 오른쪽으로 그려진다.
- 게이지와 막대는 이전 값에서 새 값까지 이동하며, 매번 0부터 다시 시작하지 않는다.
- 마우스나 손가락이 데이터 점에 닿으면 해당 지점이 커지고 툴팁이 가까운 빈 공간에 나타난다.
- 데이터가 많은 표와 그래프에서는 한 번의 진입 효과만 사용하고 스크롤 중 반복 재생하지 않는다.
- 숫자는 움직임이 끝난 뒤가 아니라 변화 과정과 함께 갱신하되 읽기 어려운 빠른 숫자 회전은 피한다.

## 상태와 데이터 흐름

모션은 저장 데이터와 분리된 표현 계층이다. 기존 업체, 계약, 체크리스트, 매출, 리포트, 키워드 데이터 형식은 변경하지 않는다.

1. 사용자의 입력을 받는다.
2. 즉시 로컬 시각 피드백을 표시한다.
3. 저장이 필요한 동작은 처리 중 상태를 보여준다.
4. 서버 성공 시 확정 상태로 안착한다.
5. 실패 시 데이터와 화면 상태를 일치시키고 오류 및 재시도를 제공한다.

중복 클릭이나 연속 탭 전환은 마지막 사용자 의도를 기준으로 정리한다. 이전 애니메이션 완료를 기다리느라 조작이 막히지 않아야 한다.

## 접근성과 성능

- `prefers-reduced-motion: reduce`에서는 이동·확대·스프링을 제거하고 100ms 안팎의 페이드와 즉시 상태 변경만 사용한다.
- 키보드 포커스와 마우스 호버를 구분하며 포커스 테두리를 모션으로 숨기지 않는다.
- 깜빡임, 빠른 반복, 큰 배경 이동은 금지한다.
- 주요 전환은 모바일 화면과 저성능 환경에서 끊김 없이 동작해야 한다.
- 레이아웃을 반복 계산하는 속성 대신 합성 가능한 속성을 우선한다.

## 오류 처리

- 네트워크 저장 실패는 성공 모션을 재생하지 않는다.
- 낙관적 업데이트가 실패하면 이전 상태로 복원하고 이유와 재시도를 함께 표시한다.
- 팝업이나 메뉴가 비정상적으로 중단되어도 배경 잠금과 포커스가 남지 않아야 한다.
- 모션 코드가 실행되지 않더라도 모든 버튼, 링크, 저장, 조회 기능은 정상 작동해야 한다.

## 검증 기준

- 버튼, 카드, 메뉴, 탭은 입력 직후 시각 반응이 나타난다.
- 빠른 연속 클릭과 전환 중 반대 조작에도 화면이 멈추거나 엇갈리지 않는다.
- 저장 성공, 처리 중, 실패 상태가 서로 명확히 구분된다.
- 업체 상세, 체크리스트, 달력, 그래프의 핵심 기존 기능 테스트가 유지된다.
- 모바일 너비에서 가로 넘침이나 클릭 영역 축소가 발생하지 않는다.
- 모션 최소화 환경에서 공간 이동이 제거되고 기능이 동일하게 유지된다.
- 브라우저 실제 화면에서 홈, 업체 상세, 체크리스트, 달력, 키워드 그래프의 대표 흐름을 확인한다.

## 단계별 출시

1. 공통 모션 토큰과 버튼·카드·메뉴·탭·팝업을 적용한다.
2. 업체 상세·체크리스트·달력의 상태 전환을 적용한다.
3. 그래프·게이지·데이터 툴팁을 적용한다.

각 단계는 독립적으로 테스트하고 배포할 수 있게 구성한다. 한 단계에서 회귀가 발견되면 다음 단계로 넘어가지 않는다.

## 제외 범위

- 소리와 진동 피드백
- 3D 효과나 장시간 배경 애니메이션
- 데이터 구조, 인증, 저장소 변경
- 모션 적용을 위한 대규모 화면 재설계
